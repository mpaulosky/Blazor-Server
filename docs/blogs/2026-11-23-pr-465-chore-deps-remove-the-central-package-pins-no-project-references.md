# chore(deps): Remove the central package pins no project references

- **Release tag:** `v0.0.187`
- **Source PR:** [#465](https://github.com/mpaulosky/Blazor-Server/pull/465)

## PR description

### Why

`CentralPackageTransitivePinningEnabled` is on, so a `PackageVersion` no project references still pins that package wherever it comes in
through another one. Dependabot doesn't raise such a pin when it bumps the package that needs it, so the bump fails restore with NU1109.
IssueManager's all-nuget PRs (mpaulosky/IssueManager#340, mpaulosky/IssueManager#351) both failed that way.

The Baseline's new central pins check (mpaulosky/Application_Factory#110, for mpaulosky/Application_Factory#105) fails on such a pin in the
gate and in `Build Solution`. This PR removes this repository's pins before the Rollout that brings the check, so the Rollout PR stays green.

### What changed

`Directory.Packages.props` loses the three pins no project references: FluentValidation.DependencyInjectionExtensions,
NSubstitute.Analyzers.CSharp and MessagePack. With MessagePack gone, the `Transitive overrides` group is empty, and is removed with its comment.

The MessagePack pin (GHSA-qhrr-8q5h-9q3h) is no longer needed: Aspire.Hosting and Aspire.Hosting.AppHost 13.6.5 ask for MessagePack 2.5.307
themselves, so it resolves to 2.5.307 without the pin, although StreamJsonRpc still asks for 2.5.302.

### Verification

- `dotnet restore` and `dotnet list package --include-transitive`, before and after: every package resolves to the same version in every
  project, MessagePack 2.5.307 in AppHost, AppHost.Tests.Integration and UI.Tests.E2E included.
- `dotnet list package --vulnerable --include-transitive` lists no vulnerable package, before or after.
- The central pins check passes on this branch.
- The gate passes (build and tests).
- The local review passed after one round.
